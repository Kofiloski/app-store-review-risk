# visionOS Review Focus

Use after the target matrix identifies a visionOS app target.

## Apply First

- App Review Guidelines globally.
- Human Interface Guidelines for visionOS windows, volumes, immersive spaces, spatial input, comfort, accessibility, scale, depth, and shared space behavior.
- Developer docs for ARKit, RealityKit, immersive spaces, world sensing, hand input, camera/privacy permissions, and spatial media.

## Review Closely

- Immersive or spatial experiences must avoid comfort issues, disorientation, misleading real-world placement, and unexpected takeover of the user's space.
- Privacy-sensitive spatial APIs, world sensing, camera-like behavior, hand/body data, location, microphone, and photos need clear permission value and App Privacy alignment.
- UI controls need appropriate scale, spacing, focus, hand/eye input ergonomics, and accessible alternatives.
- Windows, volumes, and immersive spaces should have predictable transitions, dismissal, persistence, and state restoration.
- Shared iPad/iOS code should not be assumed compliant; verify visionOS-specific navigation, layout, comfort, and accessibility.
- Generative or AI spatial content should avoid misleading representations, harmful content, or unsafe real-world instructions.

## Common Missing Evidence

- visionOS screenshots or capture notes.
- Privacy explanation for spatial inputs.
- Review notes for immersive flows and hardware requirements.
- Accessibility/comfort verification.
- Sample assets or account state needed to enter immersive scenes.
